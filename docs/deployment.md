# Secure deployment guide

Target Worker URL (verify in Cloudflare before using): `https://godot-mcp.simaklaw-vl.workers.dev`.

## Current status

- PR #1 contains the initial MCP Worker and Godot project scaffold.
- PR #2 contains a guarded, manual-only deployment workflow.
- Neither PR being green means the Worker is deployed. The deployment workflow must be on `main`, the scaffold must already be merged, and the final manual deployment must succeed.

Do not add credentials or attempt deployment until both pull requests have been reviewed and merged. No secrets belong in the repository or in commit contents.

## GitHub repository secrets

After the reviewed changes are on `main`, open this repository's **Settings → Secrets and variables → Actions** and add:

- `CLOUDFLARE_ACCOUNT_ID`: the Cloudflare account ID.
- `CLOUDFLARE_API_TOKEN`: a scoped Cloudflare API token that can edit Workers for that account.
- `MCP_BEARER_TOKEN`: a long random secret generated by a password manager.
- `FITPULSE_GITHUB_TOKEN`: a fine-grained GitHub token restricted to this repository, with Metadata read, Contents write (for repository dispatch), Issues write, and Actions read.

The deployment workflow maps the Actions secret `FITPULSE_GITHUB_TOKEN` to the Worker runtime secret `GITHUB_TOKEN`, which is the name expected by `src/index.ts`.

Do not paste any of these values into chat, source code, issue text, or Grok. Only enter the MCP bearer token into Grok if its connector explicitly requires bearer authentication. Never give Grok the GitHub token.

## Manual deployment procedure

1. Confirm PR #1 and PR #2 have been reviewed and merged, in that order.
2. Confirm a Cloudflare Worker named `godot-mcp` exists and the hostname above belongs to your account.
3. Add the four repository secrets listed above.
4. Open **Actions → Deploy FitPulse MCP → Run workflow** and run it from the `main` branch. It checks required secrets, type-checks the Worker, deploys it, configures runtime secrets, and tests the health endpoint.
5. Confirm `https://godot-mcp.simaklaw-vl.workers.dev/health` returns JSON containing `"ok":true`.
6. Configure the MCP client to use `https://godot-mcp.simaklaw-vl.workers.dev/mcp` and the MCP bearer token if the client requests one.

The deployment workflow is intentionally manual-only; merging it does not trigger a deployment by itself.

## Validation and limitations

The Godot CI validates project import and attempts to load the main scene in headless mode. It does not prove exercise biomechanics, visual quality, long-form animation playback, or Android integration. The MCP endpoint is a GitHub-backed prototype, not a remote interactive Godot editor or a production exercise-animation generator.
